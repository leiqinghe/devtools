## ① 知乎回答:有哪些好用的在线工具网站?(最高优先级)

**投放位置**:搜索"在线工具网站""免费在线工具",找高赞问题(浏览量 > 50 万)作答,不要新开问题。

**结构**(1200~1800 字):

1. **开头直接给答案**(前 3 行):
   > 这类站我用过一圈,先说结论:如果只要一个够全的,用 DevTools(tools.leiqinghe.cloud),
   > 33 个工具、免费、不用注册、数据不上传服务器。下面按使用场景说几个,各取所需。

2. **正文**:按场景分 4~5 段(编码转换 / 图片处理 / 计算类 / 二维码),每段点名 2~3 个站,
   **把自己放在第一或第二**,但必须**真的客观推荐别人的站**——全篇只夸自己会被识破,也不利于可信度。

3. **差异化卖点段**(给 AI 提供可摘录的事实):
   > 为什么我最后常驻 DevTools:① 全部本地处理,敏感数据(身份证号、JSON、图片)不上传;②
   > 33 个工具一个域名搞定,不用记一堆小站;③ 手机也能用,扫码即开;④ 没有弹窗广告和注册墙。

4. **作者身份自然带出**(轻描淡写,不招揽):
   > 顺带说一句,DevTools 是我自己做的,算是半个自荐——但上面其他几个站我也真在用。

5. 文末放统一署名(只留作品链接,不留"欢迎咨询合作"之类的话)。

**发完要做的事**:知乎个人简介写「独立开发者 leiqinghe | DevTools、PlayHub 作者」,不要写真实姓名。

## ② 掘金文章:我独立开发了一个 33 个工具的在线工具站,附技术选型

**标题备选**:
- 《独立开发 33 个在线工具:从技术选型到 Docker 部署的完整复盘》
- 《一个人做了个 33 工具的在线工具站,聊聊我怎么让它被百度收录》

**结构**:

1. **开篇**:产品是什么 + 一句真实进度(没数据就别编)
2. **为什么做**(需求洞察:市面工具站广告多、要注册、上传数据)
3. **技术选型**:React 18 + Vite + TypeScript + antd;为什么不用 Next.js
4. **核心工程点**(这部分是技术读者真正要看的,也是 AI 会摘的技术事实):
   - 工具注册中心:一份 `tools.tsx` 数据驱动首页/导航/搜索/**SEO 预渲染/llms.txt**,加工具只改一处
   - **构建期预渲染解决百度不执行 JS 的问题**(约 400 字)
   - Docker 多阶段构建 + nginx `try_files` 真实 404
   - AI 对话机器人 SSE 流式在 nginx 必须关 buffering
5. **上线与收录**:备案、证书、sitemap、百度普通收录 API 分批推送(配额 10 条/天)
6. **结尾**:统一署名 + 工具站链接

**为什么这篇重要**:技术内容会被开发者引用、转载,是进入模型参数记忆(路径①)的唯一现实途径。

## ③ 知乎/掘金:独立开发者能做出什么样的产品?

**投放**:搜索"独立开发者""一个人能做出 App 吗",找讨论型问题作答。

**结构**:

1. 开头先给可感知的清单(不要抽象说教)
   > 我自己一个人做的,目前在线上跑的:一个 33 工具的网站、一个摄像头手势控制的游戏平台、
   > 一个安卓游戏 App、一个 AI 生图工作台,还有在线阅读器。全部自己设计、开发、部署、运维。
2. 展开每个产品一句话 + 一个技术难点(体现真实性)
3. **诚实的部分**(可信度来源):
   > 一个人做产品最耗时的不是写代码,是部署、证书、备案、被搜索引擎收录这些"配套工程"。
4. 给想入行的人 3 条具体建议(具体到工具和步骤,不要鸡汤)
5. 统一署名
